# Decisions log

Running log of product/architecture decisions made during the build that
aren't already pinned down in `docs/build-package/`. Newest first.

## Phase 0 — Kickoff

- **Monorepo layout**: adopted `02_ARCHITECTURE.md`'s layout unchanged
  (`apps/web`, `apps/agent`, `packages/core`, `packages/ai`,
  `packages/render-web`, `packages/ui`) — it's sound and there's no reason
  to deviate.
- **AAC audio encoding in WebCodecs**: not reliably available outside
  Chrome/Chromium. Plan: encode AAC where `AudioEncoder` supports it, fall
  back to Opus with a visible "for best compatibility, render in Chrome"
  notice, per the spec's own fallback language.
- **File System Access API** (folder linking, direct-to-disk save): Chromium
  only. Plan: feature-detect; fall back to drag-and-drop import and a
  standard browser download for the rendered MP4.
- **In-browser Whisper**: WebGPU gives good speed; WASM fallback will be
  slower on long audio. Plan: chunk aggressively (30 s windows with
  overlap, per `04_RENDER_PIPELINE_REFERENCE.md`) and show progress/ETA
  rather than let it look hung.
- **Git identity for commits made by the build**: `Ninja
  <andacover.tv@gmail.com>`, matching the repo owner.

## Phase 1 — Scaffold + core + AI layer

- **Neither the cloud build environment nor the sandboxed local shell can
  reach `registry.npmjs.org`** (403 Forbidden from both, by network
  policy). Every file in this phase was written by hand against
  `02_ARCHITECTURE.md` / `05_AI_PROVIDER_SPEC.md` / `04_RENDER_PIPELINE_
  REFERENCE.md` and has NOT been through `pnpm install`, lint, typecheck,
  or the test suites. This breaks the "finish each phase with lint +
  typecheck + tests green" rule in `03_BUILD_PROMPTS.md` — the fix is for
  you to run the install/verify commands yourself in a normal terminal
  with real internet access, and report back anything that fails so it can
  be corrected before Phase 2 starts.
- **Key persistence**: the Zustand provider store in `apps/web` currently
  keeps API keys in the in-memory `KeyStore` only (cleared on page
  reload). The encrypted-blob-in-IndexedDB persistence layer and the
  passphrase unlock/lock UI are still open — `encryptSecret`/
  `decryptSecret` exist in `packages/ai/src/keystore.ts` and are unit
  tested, but nothing calls them from the Settings page yet. Flagged here
  rather than silently deferred.
- **shadcn/ui**: not installed (`packages/ui` is an empty placeholder).
  Its CLI needs an interactive `pnpm dlx shadcn@latest init` with network
  access, which isn't available in this session. `apps/web` uses plain
  Tailwind classes for now; swapping in shadcn/ui components is a
  non-breaking follow-up whenever it's run once, by hand.
- **No `pnpm-lock.yaml`** committed yet — it's generated by the first real
  `pnpm install` and should be committed once that succeeds.
